# ⏳ Focus & Cafe Roulette — 集中力最大化・時間管理 Web アプリ

> 「自宅なのに集中できる」を、システムの力で実現する。

---

## 🎯 開発の背景 (Background)

TOEIC とインターン選考という2つの締め切りを抱える中で、自宅学習での集中力維持が最大の課題になりました。

既存のタイマーアプリやポモドーロ手法を実際に試しましたが、**根本的な問題**に気づきました。

> 「何をするか」の選択権がユーザーに委ねられている限り、意志力が弱い状況では必ず娯楽へ逃げる。

この問題を解決するために環境を分析した結果、**図書館**が集中できる理由は「静けさ」ではなく、**「行動選択の自由度が低いこと（制約環境）」** にあると仮説を立てました。

本プロジェクトは、この「制約環境」を自宅の PC 上で疑似再現することを目的に開発しました。

---

## 💡 課題分析と設計思想 (Design Thinking)

単なる計測・記録ツールを作るのではなく、**人間の心理的ハードルを逆用する**という設計方針を定めました。各機能はそれぞれ独立した心理的根拠を持っています。

| # | 課題 | 設計で解決した方法 |
|---|---|---|
| 1 | 「何をするか」迷って時間を浪費する | **ランダム提示**でシステムが行動を決定 |
| 2 | 休憩を連続して選び、休みが常態化する | **連続選択ロック**で強制的なガードレールを構築 |
| 3 | タイマーを見るほど「残り時間」が気になり集中が途切れる | **勉強中タイマー非表示**で時間強迫観念を排除 |
| 4 | 締め切りが「いつか遠い未来」に感じられ緊張感がない | 残り日数を「**あと〇〇時間**」という行動量に変換 |
| 5 | 集中が途切れたとき、そのまま長時間サボりに移行する | **SOS 機能**で「中断」を罪悪感なく受け入れ、即リセット |

## 🚀 機能一覧 (Features)

### コア機能（制約ロジック）

#### 1. カフェルーレット（ランダム提示）
勉強タスクと気分転換タスクをシステムがランダムに提示します。重点強化したいタスクは「フォーカスリスト」に登録することで抽選確率が3倍になります（TOEIC 対策向けに設計）。

#### 2. 連続選択ロック
「気分転換」を実行した直後は、次のルーレットで気分転換が選択肢から除外されます。「勉強 → 休憩 → 勉強 → 休憩」というリズムを**システムが強制**します。

#### 3. 可変タイマー UI（没入設計）
- **勉強中**: タイマーを非表示。終了ボタンも制限時間が来るまで表示されない仕様にすることで、タスクへの完全没入を促進。
- **気分転換中**: カウントダウンを表示し、終了時に音で通知。休憩の長引きを防止。

#### 4. マイルストーン残存時間の可視化
TOEIC・インターンそれぞれの目標期日と1日の予定学習時間を入力すると、**「あと〇〇時間使える」** という残作業可能時間をリアルタイムで算出・表示します。

#### 5. 今日の進捗ダッシュボード（CSS 製ドーナツグラフ）
`conic-gradient` を使ったピュア CSS の円グラフで、当日の勉強時間を視覚的に表示します。目標達成率に応じてグラフがリアルタイムで更新されます。

#### 6. SOS 緊急リセット機能
集中が途切れた際に「集中切れ！（SOS）」ボタンを押すと、それまでの経過時間を記録した上で「瞑想」「深呼吸」「腹筋30回」などのリセット行動をランダムに指示します。**中断を記録上の失敗ではなく、次への準備として扱う**設計思想です。

#### 7. ゲーム解放条件ロジック
「20時以降 かつ 当日目標時間達成」の場合にのみ、ゲームが気分転換の選択肢に追加されます。勉強量という客観的指標でゲームをロック解除することで、娯楽を報酬として機能させます。

### サポート機能

#### 8. 環境音 BGM プレイヤー（YouTube IFrame API）
YouTube IFrame API を用いたカスタム BGM コントローラーをサイドバーに実装。「☕ カフェ」「🗣️ 雑踏」「🐋 波と鯨」の3種の環境音をワンクリックで切り替え・ループ再生できます。

> **開発上の知見**：初期実装では動画 ID が誤っていたため意図しない BGM が再生される不具合が発生。YouTube の仕様上 ID は外部に依存するため、日本語の作業用環境音動画を選定し直しました。外部リソースへの依存箇所は継続的な動作確認が必要という教訓を得ました。

#### 9. コンパクト没入モード（🗕ボタン）
ボタン1つで UI を最小化し、背景画像をほぼ全画面表示にできます。タスク名と残時間だけを半透明パネルで小さく表示することで、「カフェの窓際で作業している感覚」を演出します。

#### 10. スト6 コンボ練習アプリ（組み込みミニゲーム）
気分転換タスクの1つ「スト6 コンボ練習」を選択すると、Streamlit 内に完全なコンボ解析アプリが起動します。キーボードと**Web Gamepad API**によるコントローラー両対応で、フレーム単位の入力解析・コンボ成功ログ・入力エラーの指摘を行います。「娯楽も中途半端にしない」という設計ポリシーから生まれた機能です。

#### 11. 設定パネル（永続化）
勉強リスト・フォーカスリスト・気分転換リスト・目標期日・背景画像 URL などをすべて UI から編集し、`settings.json` に保存。アプリを再起動しても設定が引き継がれます。

#### 12. アクティビティログ（CSV 出力）
実行したすべてのタスク（カテゴリ・内容・経過時間・日時）を CSV に記録し、サイドバーからダウンロードできます。「中断」「SOS」も区別して記録されるため、自分の集中パターンを事後分析できます。

## 🔧 実装上の技術的工夫 (Technical Highlights)

**1. Streamlit × JavaScript の状態非同期問題への対応**

Streamlit はページが再レンダリングされるたびに Python の状態が再評価されますが、`components.html()` 内の JavaScript は独立したセッションで動作します。タイマーのリセット防止のために `sessionStorage` を活用し、Python 側の再レンダリングと JavaScript 側のタイマー状態を切り離しました。

**2. Gamepad API のポーリングループ実装**

Web Gamepad API はイベント駆動ではなくポーリング方式のため、`requestAnimationFrame` で毎フレーム入力状態を取得するゲームループを JavaScript 内に実装しました。方向キーの変化検出・ボタンの押下エッジ検出（前フレームとの差分）を行い、格闘ゲームの入力受付に近い精度を実現しています。

**3. グラスモーフィズム UI の背景設定**

Streamlit はデフォルトでアプリ背景を制御できないため、`components.html()` 経由で JavaScript を注入し、親フレームの `.stApp` 要素に直接スタイルを適用する方法を採りました。`backdrop-filter: blur()` と半透明背景の組み合わせで、背景画像を活かしたグラスモーフィズムデザインを実現しています。

## 📈 成果と振り返り (Results & Reflection)

- **企画から実装まで約2週間**で動作するプロダクトを完成。
- 実際に日々の学習に使用しており、TOEIC 学習・インターン準備のスケジュール管理ツールとして機能しています。
- Streamlit を選択したことで Python のみで多機能な Web アプリを素早く構築できた一方、`components.html()` を多用する形になり「フレームワークの想定外の使い方」をしている箇所が増えました。本番サービスを想定するなら Flask + React など責任分離を明確にした構成が適切と認識しています。
- 生成 AI（Gemini）との協働において、アルゴリズムを自然言語で仕様定義してコードに落とし込むプロセスを経験し、「何を作るかを正確に言語化する能力」がエンジニアリングの質に直結することを実感しました。
